# Material extraction: next experimental direction (2026-10-01)

**Scope correction (2026-10-01):** This note addresses only how a synthetic CLEVR Material training set might improve the existing `<M*>` LoRA. The project owner's intended question is the broader ICE task: extract material from a natural source image and construct material counterfactual image pairs. The corrected research protocol is in `../subject_material_composition_v1/diagnostics/natural_material_counterfactual_design_20261001.md`. Do not use the synthetic caption-only pilot below as the answer to that broader question.

## Objective and current evidence

Here, "extract material" means learning an `<M*>` conditioning signal that transfers metallic surface appearance across objects while ordinary prompt words retain shape and color control. It does not mean estimating physical roughness/metallicity maps from one image.

The selected LoRA baseline is frozen in `frozen_result_20261001.md`. The current Material staging has 72 images of CLEVR `MyMetal` across three shapes, four colors, three lighting conditions, and two views. All training rows use `a photo of an object made of <M*>`; there is no matched nonmetal training condition. The foreground object mask is available and used for masked denoising loss. The `MyMetal` asset does not expose metallic, roughness, and specular parameters as independently controlled values in this staging. In the fixed S+M diagnostics, increasing M Key attention or Value residual strength did not reliably recover metallic appearance. This pattern is compatible with material, shape, color, lighting, and rendering-style information sharing the learned M signal; it does not prove a unique cause.

The project also has an existing 360-render CLEVR metal/rubber paired set in `clevr_subject_color_material_3x3x2/20260826-104500__clevr_subject_color_material_3x3x2__multiview-render-v3-material__d1f4282__420000` under the server run root. Its pairs fix render seed, geometry, camera, and lighting while changing material; an earlier review noted some metal upper/lower reflection differences and rubber highlights. Treat those as appearance limitations when selecting pairs.

## Smallest interpretable sequence

1. **Caption-only pilot:** keep the existing 72 images, masks, LoRA mode/rank/alpha, steps, seed, and sampling protocol. Replace the one generic training sentence with verified per-image shape and color words, e.g. `a photo of a red sphere made of <M*>`. This requires an isolated per-image caption staging/loader path. Hypothesis: ordinary words explain shape and color, leaving `<M*>` to explain more surface appearance. Compare against the frozen M checkpoint with the same 36-image S/M grid and material-only held-out objects.
2. **Paired-data pilot if needed:** use the already rendered metal/rubber pairs as controlled references. Keep matched sample count and the caption format fixed against the prior pilot while changing only the image cohort. Train on metal examples across varied views/lights; reserve corresponding rubber images for paired visual audits. This tests whether greater appearance diversity helps the token. Merely adding rubber rows with no `<M*>` to the current token-local optimizer would not give the M-only LoRA residual a direct gradient, so a true contrastive or paired objective is a separate method experiment.
3. **Conditional material editing if token learning remains weak:** train an image- and mask-conditioned edit from one material to another using matched pairs. This can better control geometry and lighting, but it is a different inference interface from composing `<S*> + <M*>` in text-to-image generation; evaluate it separately.

For each stage, score material transfer, mailbox identity, red/blue obedience, unwanted shape/color/background changes, and variation across the previously failing seeds. Use blind human comparison alongside the paired renderer references; the project's earlier Qwen evaluation labeled most ground-truth rubber examples as `other`, so its absolute rubber labels should not be the sole gate.

## Relevant primary papers

- [ColorPeel (ECCV 2024)](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/01191.pdf): varies shapes to learn abstract color tokens and demonstrates a small material-token extension. The caption-only pilot applies its disentanglement idea to the existing M images; its material result is not evidence that this project's natural mailbox transfer is solved.
- [Alchemist (CVPR 2024)](https://openaccess.thecvf.com/content/CVPR2024/papers/Sharma_Alchemist_Parametric_Control_of_Material_Properties_with_Diffusion_Models_CVPR_2024_paper.pdf): renders controlled changes to metallicity, roughness, albedo, and transparency while holding the paired scene setup fixed. Most directly supports a matched material counterfactual dataset.
- [DreamMat (2024)](https://arxiv.org/abs/2405.17176): conditions on geometry and lighting and varies environment lights to prevent highlights from being baked into material parameters. Supports varied light and explicit reflectance checks; its 3D PBR pipeline is not directly interchangeable with a text token.
- [MatSwap (Eurographics 2025)](https://diglib.eg.org/bitstream/handle/10.1111/cgf70168/cgf70168.pdf): uses material examples with geometry- and lighting-aware diffusion for masked material transfer. Relevant to the conditional-edit fallback, not a drop-in K/V LoRA change.
- [RGB-X (SIGGRAPH 2024)](https://arxiv.org/abs/2405.00666): estimates intrinsic channels including albedo, roughness, metallicity, and lighting. Useful if the goal changes to physical material extraction; single-image estimates remain ambiguous and must be validated on this domain.
