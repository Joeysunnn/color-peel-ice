# Natural-image material extraction and counterfactual pairs for ICE (2026-10-01)

## Task boundary

The objective is to start from a **natural image**, identify an object and its visible material/finish, and produce a paired counterfactual in which the intended material factor changes while object identity, geometry, color designation, viewpoint, illumination, and scene remain controlled. This is a data-construction stage upstream of ICE/ColorPeel Subject and Material token training. ICE Stage One provides text-associated object masks; ICE Stage Two learns semantic intrinsic-concept tokens such as material. ICE's semantic material concept is not itself a measured metallicity or roughness map.

The target must be named precisely. For a painted mailbox, a photo may support an inference about *visible surface finish* (for example, crisp specular metal-like reflection versus broad matte response) but cannot reliably reveal whether the substrate beneath opaque paint is metal or plastic. A first counterfactual should alter one visible factor, such as roughness or a clearly specified metal-like versus diffuse finish, with base color held as closely as physical rendering permits. Do not treat identical RGB pixels as a realistic requirement after a BRDF change.

## Existing natural-image pilot and its limit

`protocols/mailbox_matte_counterfactual_v2.json` uses one generated matte edit of the green natural mailbox photo, resizes it, recolors it to five hues, and composites the object region onto each original background. Its source protocol records five color variants of the same mailbox image. The earlier audit found identical object masks and background pixels across all ten metal/matte balanced rows. The edited reference also changed background pixels before masked compositing and may alter mailbox details inside the mask. These outputs are useful editing candidates, but they are not independently observed material views or physical ground truth. They should remain labeled `generated_counterfactual` and grouped under one source-photo identity during any train/test split.

## Proposed extraction and construction protocol

1. **Natural source and localization.** Register every original photo, its license/source, camera/view if available, object category, and stable object ID. Use ICE Stage One or a reviewed segmentation mask to isolate the object. Mark subregions whose materials differ (body, handle, mounting hardware) and a separate reflection/shadow influence zone. Preserve the original RGB as the anchor.
2. **Material interpretation.** Record a human-reviewed visible-material description and uncertainty. Estimate optional intrinsic maps such as albedo, normal, roughness, metallicity, and illumination using an RGB-to-intrinsics model. Treat those maps as hypotheses; require that an unchanged re-synthesis approximately reconstruct the source object and highlights before trusting any edit. Multiple views or lighting observations should be preferred whenever possible because a single image cannot uniquely separate reflectance from illumination.
3. **One-factor counterfactual.** Create a target material/finish spec before editing. Route A edits roughness/metallicity or a material exemplar in intrinsic/PBR space and re-synthesizes the source scene. Route B uses a masked, geometry- and lighting-aware material transfer model conditioned on a reference material crop. Keep segmentation, object pose, camera, source-specific details, background, and intended base-color parameter fixed; allow physically necessary changes in reflections and cast light within a documented influence zone. Generate several candidates per source; do not silently select an attractive image.
4. **Pair acceptance.** Require unchanged background outside the object/influence zone, stable silhouette and landmarks (seams, ridges, mailbox flag/handle), preserved text/decoration, aligned object mask and normals/edges, and a visible material difference in the intended region. Review original, unchanged reconstruction, counterfactual, difference map, and material estimate side by side. Reject pairs where geometry or color changes explain the apparent material difference. Record pass/fail and uncertainty per source image.
5. **Dataset split and evaluation.** Version each accepted pair with hashes of source, mask, estimated maps, edit method/model/config/seed, output, and review. Keep all variants derived from one photo together in a split. Hold out different natural object identities, views, and scene contexts for transfer tests. Report material change, identity/geometry preservation, color adherence, scene preservation, and failure rate separately; do not promote generated images to ground-truth material captures.

## Minimal pilot

Start with the existing **original green mailbox photo** and its reviewed mask as one source case. Produce an unchanged reconstruction and at least one metal-like-to-matte candidate using an intrinsic or material-transfer method, then compare them with the existing image-edit matte candidate. This is an editing-feasibility check only. A dataset intended to teach an ICE-level transferable material concept needs genuinely different natural objects or independent views and lighting conditions; five recolors of one photo do not meet that requirement. No new token training should be interpreted as a material-extraction result until the pair acceptance gate passes.

## Primary method references and suitability

| Paper | Relevant mechanism | Main caveat for this mailbox |
| --- | --- | --- |
| [ICE (CVPR 2025)](https://arxiv.org/abs/2503.19902) | Text-associated object masks followed by semantic intrinsic-concept learning. | Does not directly recover physical BRDF maps or verified counterfactual pixels. |
| [Material Palette (CVPR 2024)](https://arxiv.org/abs/2311.17060) | Extracts a masked material region from a real photo, generates texture samples, estimates albedo/normal/roughness maps. | Best as an exemplar/material-prior route; does not by itself recover the full mailbox's lighting or metallicity map. |
| [MaterialPicker (2024)](https://arxiv.org/abs/2412.03225) | Estimates albedo, normal, roughness, height, and metallicity from possibly distorted/occluded natural-image material crops. | A crop-based material sample is not a full scene reconstruction or finished paired edit. |
| [RGB-X (SIGGRAPH 2024)](https://arxiv.org/abs/2405.00666) | Estimates albedo, normal, roughness, metallicity, and lighting, then synthesizes from intrinsic channels. | Trained/evaluated mainly for interiors; authors report higher variance for metallicity/roughness, especially without informative lighting. Validate on outdoor mailbox before use. |
| [IntrinsicEdit (SIGGRAPH 2025)](https://arxiv.org/abs/2505.08889) | Identity-preserving editing in intrinsic-image space with local material/roughness changes and resynthesis. | Needs a source-domain pilot and unchanged-reconstruction check. |
| [MatSwap (Eurographics 2025)](https://arxiv.org/abs/2502.07784) | Masked material transfer from a reference patch with geometry- and lighting-aware diffusion. | Gives image-level appearance transfer, not necessarily physical material parameters. |
| [Alchemist (CVPR 2024)](https://openaccess.thecvf.com/content/CVPR2024/papers/Sharma_Alchemist_Parametric_Control_of_Material_Properties_with_Diffusion_Models_CVPR_2024_paper.pdf) | Controlled counterfactual training pairs vary metallicity, roughness, albedo, or transparency within the same rendered scene. | Its controlled pairs are synthetic; the design principle informs our natural-image pair gate, not automatic real-photo ground truth. |
